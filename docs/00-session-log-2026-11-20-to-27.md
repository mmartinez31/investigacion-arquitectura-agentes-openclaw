# Log de sesión de diseño — Nov 20-27, 2026

## Contexto que disparó la investigación

El bug CID=00202601 en Timesheets: el refactor Developer→TeamMember (migración V12 de Flyway) dejó al Admin sin permisos. La UI no mostraba ningún mensaje de error — 403 silencioso. Miguel descubrió el problema al intentar crear a Efrain manualmente.

Esto abrió la pregunta: ¿por qué los agentes de IA no siguen los patrones documentados, y cómo cambiar la infraestructura para que sí los sigan?

---

## Decisiones tomadas

### 1. Patrón no-silent-errors (documentado en KB)
Ubicación: `knowledge-base/07-ui-ux/10-no-silent-errors-pattern.md`
Todo feedback de acción en UI es obligatorio. Auditado en los 3 sistemas (Timesheets, Sales 360, TPP).

### 2. Tres causas raíz por las que los patrones no se siguen
- Context dilution: las reglas leídas al inicio del contexto pierden peso conforme el turno crece
- Happy path bias: los agentes optimizan para que el feature funcione; error handling es overhead implícito
- Sin enforcement mecánico: las reglas en Markdown no fallan un build

### 3. Diseño de enforcement en tres capas
- Capa 1 (mecánica, CI/CD): scripts que fallan el build si detectan anti-patrones concretos
- Capa 2 (spec gate): antes de codificar, el agente produce un micro-spec con KB patterns aplicables y espera OK de Miguel
- Capa 3 (repo AGENTS.md): checklist específico del stack en cada repo, inyectado al inicio del brief del worker

### 4. Skills vs Workflows: aclaración arquitectónica
- Skills (OpenClaw): playbooks en Markdown que el agente lee e interpreta. Buenos para procedimientos reutilizables. No tienen estado propio ni garantías de ejecución.
- Workflow (Claude Code): scripts JavaScript que orquestan agentes con `agent()`, `pipeline()`, `parallel()`, `phase()`. Tienen journal (resume desde checkpoint), structured output via schema, budget control. Son la herramienta correcta para tareas largas y multi-paso.
- OpenClaw no delega "a" Claude Code — OpenClaw está construido sobre Claude Code. Son la misma pila.

### 5. Para tareas largas: usar Workflow de Claude Code
Decisión: todo proceso con >3 items, >15 min estimados, o que pueda fallar a mitad debe correr como Workflow (no como sessions_spawn libre).

### 6. Problema abierto: selección dinámica de estrategia
Pregunta de Miguel: ¿cómo sabe el agente automáticamente que necesita un Workflow, cómo lo construye, y cómo maneja procesos robustos anidados (workflow dentro de workflow)?

Ejemplo concreto: "revisa todos los consultores del TTP sin fecha de ingreso y para cada uno busca contratos y aumentos" — proceso exterior (N consultores) + proceso interior por cada uno (buscar archivos).

Límite conocido del Workflow tool: `workflow()` dentro de un child lanza error — un solo nivel de anidamiento.
